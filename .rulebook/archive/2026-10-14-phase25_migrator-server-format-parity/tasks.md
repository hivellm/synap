## 1. Implementation
- [x] 1.1 Move the server's snapshot and WAL codecs into one module used by both the server and `synap-migrate` — synap-migrate now depends on the synap-server library (no cycle) and its private v2 codec is gone; `SnapshotImage` fields are public, `SnapshotManager::write_snapshot` takes the stream section directly, `SnapshotCorrupted` names its reason, and `recovery::rebuild` is the file-free half of startup recovery
- [x] 1.2 Read every snapshot version and WAL format the server reads, and apply the WAL tail written after the snapshot — new `source` module: newest snapshot via the server's `SnapshotManager` (v2-v5, sequenced and legacy names), WAL via `wal_frame::scan` (legacy and v2, torn tail skipped and reported, never repaired; the scan now types the tail (`TailKind`), and a complete checksum-valid record this release cannot decode fails the read instead of being dropped as a torn tail), records from the cutoff on replayed by `recovery::rebuild`; unit tests cover both WAL formats, the cutoff, relative TTLs and torn tails
- [x] 1.3 Migrate every persisted structure with queue and stream metadata and absolute expiry, scoped for Hub mode — new `scope` module renames KV keys, hashes, lists, sets, sorted sets (geo included), HyperLogLogs and bitmaps with `MultiTenant::scope_kv_key`, queues with `scope_queue_name` and stream rooms with `scope_stream_name`; values, absolute deadlines, whole queue states (config, message IDs and metadata, dead letters) and stream events (ID, offset, timestamp) move unchanged; `--server-config` supplies queue defaults for pre-v5 input; the run prints a per-structure report with notes on what older formats cannot carry
- [x] 1.4 Write output only to a new location, and reject corrupt or unsupported input before writing anything — `migrate --output <new or empty dir>` (refused inside the source or when not empty); every snapshot file and the whole WAL are verified before writing, errors name the file and reason (checksum mismatch, unknown or newer magic, interior WAL corruption, newer WAL format, WAL records of an unknown type); input is taken for migrated data only when every name is Hub-scoped (`--allow-scoped-names` overrides; standalone `user_<UUID>:` names among others are scoped normally, with a note); output is one `snapshot-v5-<seq>.bin` (WAL cutoff 1) read back with the server loader; in-place backup/rollback commands removed (the source stays the rollback)
- [x] 1.5 Add data directory fixtures generated by real 1.3.2 and 1.4.0 servers — `crates/synap-migrate/tests/fixtures/generate_fixtures.py` drives a real server (every datatype, deletes, forced snapshot, WAL tail, Ctrl-C stop) and records `baseline.json`; committed `v1.3.2/` (1.3.2 release binary at bfecd0c: v3 snapshot, headerless WAL) and `v1.4.0/` (this branch's server: v5 sequenced snapshot, SYNAPWAL v2), with a README recording what each holds and what 1.3.2 never persisted
- [x] 1.6 Test migrating each fixture, booting the real server in Hub mode on the output, and comparing against the pre-migration baseline — `crates/synap-migrate/tests/real_server_fixtures_tests.rs` (feature `full-tests`): runs the `synap-migrate` binary on a copy of each fixture, checks the copy is unchanged and the output is one `snapshot-v5-…01.bin`, then boots Hub mode in-process (a Hub-enabled `ServerConfig` recovered by `persistence::recover_all` exactly as `main.rs` does, served by `create_router` with a `HubClient` whose access-key validator maps a test key to the tenant, because the binary answers 503 to every Hub request, hivellm/synap#230) and reads every baseline resource through `/api/v1/command` and REST as the tenant, stream events included (startup now restores a snapshot's stream rooms: `StreamManager::restore_events`, `recovery::restore_streams`, called by `main.rs` and by the test's boot), comparing IDs, offsets, types, data and timestamps; also asserts the Hub stores equal the standalone recovery of the source name for name, remaining TTLs never exceed the source's, another tenant sees nothing, and a corrupt real snapshot is rejected without output
