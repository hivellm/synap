## 1. Implementation
- [x] 1.1 Move the server's snapshot and WAL codecs into one module used by both the server and `synap-migrate` — synap-migrate now depends on the synap-server library (no cycle) and its private v2 codec is gone; `SnapshotImage` fields are public, `SnapshotManager::write_snapshot` takes the stream section directly, `SnapshotCorrupted` names its reason, and `recovery::rebuild` is the file-free half of startup recovery
- [x] 1.2 Read every snapshot version and WAL format the server reads, and apply the WAL tail written after the snapshot — new `source` module: newest snapshot via the server's `SnapshotManager` (v2-v5, sequenced and legacy names), WAL via `wal_frame::scan` (legacy and v2, torn tail skipped and reported, never repaired), records from the cutoff on replayed by `recovery::rebuild`; unit tests cover both WAL formats, the cutoff, relative TTLs and torn tails
- [x] 1.3 Migrate every persisted structure with queue and stream metadata and absolute expiry, scoped for Hub mode — new `scope` module renames KV keys, hashes, lists, sets, sorted sets (geo included), HyperLogLogs and bitmaps with `MultiTenant::scope_kv_key`, queues with `scope_queue_name` and stream rooms with `scope_stream_name`; values, absolute deadlines, whole queue states (config, message IDs and metadata, dead letters) and stream events (ID, offset, timestamp) move unchanged; `--server-config` supplies queue defaults for pre-v5 input; the run prints a per-structure report with notes on what older formats cannot carry
- [x] 1.4 Write output only to a new location, and reject corrupt or unsupported input before writing anything — `migrate --output <new or empty dir>` (refused inside the source or when not empty); every snapshot file and the whole WAL are verified before writing, errors name the file and reason (checksum mismatch, unknown or newer magic, interior WAL corruption, newer WAL format); output is one `snapshot-v5-<seq>.bin` (WAL cutoff 1) read back with the server loader; in-place backup/rollback commands removed (the source stays the rollback)
- [ ] 1.5 Add data directory fixtures generated by real 1.3.2 and 1.4.0 servers
- [ ] 1.6 Test migrating each fixture, booting the real server in Hub mode on the output, and comparing against the pre-migration baseline
